docs/05 §5.6. The host tracks live AI-tool connections + their busy state, so the API can expose "list connections" / "N working, M idle" and `run`'s Target can pick one.

Scope (in hotsheet-aitools):
- Connection record: id, project, tool (plugin id), role (Main|Worker|DriveSpawned), transport, pid/session, started_at (injected clock).
- ConnectionRegistry: register/unregister/get/list/count.
- Busy tracking via a sliding window (HS1's model, generalized): note_activity(id, now) is a heartbeat (hooks or byte-stream/spinner inference both feed it); is_busy(id, now) = elapsed < busy_window; set_idle(id) forces idle immediately (a Done signal). busy_count(now).
- Clock injected (now_ms passed in) so it's deterministic + testable.

Deferred: wiring the registry to live TurnHandle signals (a server loop notes activity while a turn is busy) — lands when drive is wired into the server. Byte-stream spinner inference itself lands with terminals (HS2-10).

Acceptance: register/list/get/unregister; a connection is busy within the window after note_activity and idle after it or on set_idle; busy_count reflects it. Deterministic under an injected clock.

Relates to: HS2-106 (drive), docs/13 §13.4 (busy is a derived view), HS2-10 (spinner inference).
