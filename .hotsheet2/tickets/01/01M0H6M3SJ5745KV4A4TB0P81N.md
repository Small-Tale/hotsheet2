Split from HS2-93 (whose trust-gate/verify half is done). This is the part of docs/05 §5.11 for plugins that carry CODE (not manifest-only data), which don't exist yet — so this is deferred until a behavioral plugin capability (drive/terminal) needs it.

Scope (docs/05 §5.11):
- Subprocess protocol (stdio JSON-RPC) for process-shaped behaviors — drive/trigger, terminals, MCP (already subprocess-shaped in HS2). An external behavioral plugin is an executable speaking the capability protocol; OS crash-isolation.
- WASM (wasmtime/extism) for pure-compute transforms wanting a tighter sandbox — host exposes only the docs/05 §5.10 adapters (ProcessSpawner, config writer, PermissionTransport, McpConfigWriter, Clock) as capability-scoped imports; ambient fs/net denied.
- Manifest schema: a behavioral capability declaration (which capability, which boundary, the module/executable path).

Acceptance: an external subprocess plugin drives hs-fake-agent through one turn; a WASM transform runs with fs/net denied.

Depends on: HS2-67 (drive trait) + HS2-64 (fake-agent). Naturally sequenced AFTER the drive capability exists.
