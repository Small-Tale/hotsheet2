The drive glue (HS2-108 host::trigger) is tested with a fake spawner. This wires it to reality: inject SystemSpawner and expose a trigger so a user/agent can actually launch a tool against a project.

Scope:
- A trigger surface: `hotsheet-cli trigger <tool> [--worker] "<prompt>"` and/or a server endpoint (POST …/trigger). Builds DriveCtx { cwd, spawner: SystemSpawner }, mints a connection id, calls host::trigger, tracks the connection in the server's registry, streams/records the turn.
- Persistent server holds the ConnectionRegistry (drive is server-only, docs/05 §5.1a); the CLI trigger without a server runs the turn synchronously and reports the outcome.
- MUST apply the HS2-103 launch-safety lessons: on a dev machine a bare `hotsheet`/tool name can hit HS1 production. The launched tool's environment must resolve our binaries (hotsheet-cli/hotsheet-mcp), and the tool must not be able to reach the HS1 launcher (see the ~/.local/bin shim + preflight + assert_no_hs1 approach in the E2E harness). Codex needs an isolated CODEX_HOME.
- Wire live TurnHandle busy into the registry (note_activity while busy; set_idle on Done).

Acceptance: `hotsheet-cli trigger codex "..."` launches a real codex exec for the project and reports Completed/Failed, with a registered connection that shows busy→idle, and HS1 is never launched.

Relates to: HS2-106/107/108, HS2-59 (server lifecycle), HS2-103 (launch safety).
