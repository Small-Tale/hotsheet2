Tie the drive pieces (HS2-106 Drive/SpawnDrive + HS2-107 ConnectionRegistry) together via the plugin manifest, so a tool's drive is data-declared and the host can trigger it. Tested with a fake spawner — NO real tool launched (the real server/CLI trigger that injects SystemSpawner + applies HS2-103 safety is a follow-up).

Scope:
- hotsheet-plugins manifest: optional [drive] table — transport (spawn|claude-channel|app-server|acp), program, args, content (arg|stdin), interrupt. Declarative/client-safe (strings). Plugin exposes it.
- Codex first-party plugin gets [drive] (codex exec). Claude stays driveless until the channel drive (HS2-9).
- hotsheet-aitools (depends on hotsheet-plugins): drive_for(plugin) -> Option<Box<dyn Drive>> — builds a SpawnDrive from a spawn-transport plugin; None for driveless or not-yet-built transports.
- Host::trigger(plugin, target, content, ctx, registry, now) — registers a DriveSpawned Connection, runs the drive, notes activity; returns the connection id + TurnHandle.

Tests: codex plugin exposes a spawn drive; drive_for builds it; Host.trigger registers a connection + runs (fake spawner) + TurnHandle busy->done; a driveless plugin (claude) -> None; a channel-transport spec -> None (not built yet).

Relates to: HS2-106, HS2-107, HS2-9 (channel drive), and a follow-up for the real CLI/server trigger.
