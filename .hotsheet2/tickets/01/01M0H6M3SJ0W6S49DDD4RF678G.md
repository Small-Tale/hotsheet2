Latent HS1 collision (surfaced during HS2-92). The server's default index path (crates/hotsheet-server/src/main.rs default_index_path) writes to ~/.hotsheet/index/<hash>.sqlite — i.e. INTO Hot Sheet 1's data dir (~/.hotsheet). HS2 should keep all machine-local state under its own home to avoid polluting/colliding with HS1.

Fix: use the same HS2 home helper HS2-92 introduced — hotsheet_plugins::hotsheet_home() = ${HOTSHEET_HOME:-~/.hotsheet2} — for the index dir too (e.g. ~/.hotsheet2/index/<hash>.sqlite). Either add a hotsheet-plugins dep to the server or lift hotsheet_home() into a shared low-level crate (hotsheet-ticketing?) so both use one definition. The index is disposable, so relocating it just triggers a rebuild — no data migration.

Acceptance: a fresh server run creates its index under ~/.hotsheet2 (or $HOTSHEET_HOME), never ~/.hotsheet; one hotsheet_home() definition shared by the plugin loader + the server.
