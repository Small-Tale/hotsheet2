Create the shared core library and the domain model: Ticket/Note/Attachment/Category/Store/Project, status+priority enums (incl. the 'moved' tombstone status), close-outcome fields (close_reason completed|not_planned|duplicate|obsolete + duplicate_of ULID + closed_at — see HS2-61), claim/lease fields; parse/serialize the Markdown+YAML-frontmatter ticket file format with a versioned `schema:` field; note ids are ULIDs. Store membership is POSITIONAL — no `store` field in ticket frontmatter (containing store root determines it), so copy/move is just relocation. Stores carry id + optional name + per-store ticketPrefix (the human "which store" signal). Policy-free, I/O via injected adapters. Blocked on the language decision (HS2-2=Rust). See docs/02-ticket-storage.md §2.2.1, §2.5, §2.6a, docs/04-core-server-cli.md §4.1.
