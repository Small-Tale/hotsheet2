Hot Sheet 2 — Architecture
One core library. The server is an independent, always-on service; every client is a pure API consumer. Ticket providers are authoritative; SQLite is a rebuildable cache.
hotsheet-core Rust crate — all domain logic, written & tested once, I/O via injected adapters
modeltickets, notes, stores, projects
providersgit default + direct external trackers
indexSQLite + FTS5
watchfs notify → reindex
queryfilter · sort · search
pluginsAI-tool host + terminals
coordclaim / lease
merge-driverautomatic conflict resolution
▲ used in-process by the two Rust binaries ▲
hotsheet-server
axum + tokio · the always-on service
Hosts the fs watcher, the index, the terminals/PTYs, and the AI-tool plugin host. Exposes HTTP REST · WebSocket · MCP. One instance per machine, serving every local project. Runs independently of any client.
hotsheet-cli
clap · direct-to-disk
Ticket ops straight against the files (works with no server running) + init / serve / reindex / migrate / doctor. A running server's watcher picks up its edits.
▼ the server exposes  HTTP  WebSocket  MCP  — localhost + secret by default, mTLS when exposed
The server is independent in every case — local included. A client that finds no server running auto-starts one (detached) and connects to it; the server keeps running after the client closes. No client embeds the core.
Tauri desktop
Web UI over HTTP/WS. Auto-starts & supervises the local server; talks mTLS to a remote server for remote projects.
SwiftUI — macOS / iOS
Native UI over HTTP/WS. macOS auto-starts the local server; iOS is remote-first (connects to a Mac's server). Android later, same API.
AI tools — Claude, Codex, …
Reach tickets over MCP (the hotsheet_* tools) or the CLI. Plugin-only — no first-class tool.
Server lifecycle (auto-start, supervision, survives client exit) and trust tiers are detailed in 04-core-server-cli.md §4.3 and 01-architecture.md §1.4.
