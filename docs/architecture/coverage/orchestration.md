Conventions used in every row:

- "Atomic JSON store" means `Storage` in `crates/hotsheet-ticketing/src/orchestration/storage.rs:146-184`: a `.orchestration-*.tmp` file in the same directory, `fsync`, an atomic replace through `hotsheet_sync::files::persist`, then a parent-directory `fsync` on Unix. A crash leaves the old or the new file and possibly a stray temp file. Machine files are mode 0600 (`crates/hotsheet-ticketing/src/orchestration/storage.rs:44-50`). Reads never create a file, refuse symlinks and special files, and treat oversized data as corrupt (`crates/hotsheet-ticketing/src/orchestration/storage.rs:107-140`). Any `schema_version` other than 1 is `UnsupportedVersion` and is never overwritten (`crates/hotsheet-ticketing/src/orchestration/storage.rs:198-211`). Test: `crates/hotsheet-ticketing/src/orchestration/tests.rs` (`hs2_4j6v46_atomic_publish_failure_leaves_exact_old_or_complete_new_bytes`, `hs2_4j6v46_fifo_data_and_lock_paths_are_rejected_without_opening_streams`).
- "File lock" means an advisory exclusive OS lock (`flock` or `LockFileEx`) on a sibling `<file>.json.lock` that is never deleted and is released when the process exits (`crates/hotsheet-ticketing/src/orchestration/storage.rs:119-124`, `crates/hotsheet-ticketing/src/file_lock.rs:1-17`). Mutations take it; most reads do not and rely on the atomic replace.
- `HOME` is the machine home, `HOTSHEET_HOME` (`crates/hotsheet-ticketing/src/orchestration/capacity.rs:973`).
- None of the components below starts a thread or task unless the row says so. Runtime loops live in the server and CLI chapters.

## Git ref compare-and-swap (`orchGitRefClaims`)

- Modules: `crates/hotsheet-ticketing/src/gitref_cas.rs`, `crates/hotsheet-ticketing/src/distclaim.rs`; small module `distwork.rs`.
- Responsibility: one marker ref per ticket (`refs/hotsheet/claims/<ULID>`) or resource (`refs/hotsheet/resource-claims/<ns>/<res>`) pointing at an orphan commit whose message is a JSON `RefMarker` (`crates/hotsheet-ticketing/src/gitref_cas.rs:28-56`). `acquire`, `renew`, `release` are compare-and-swap through `--force-with-lease` (`crates/hotsheet-ticketing/src/gitref_cas.rs:244-343`). `distclaim` and `distwork` are the older self-claim loop driven by the server every 15 s (`crates/hotsheet-server/src/dist_work_loop.rs:28`).
- State and persistence: the remote refs only; local refs are updated after a push.
- Types and entry points: `GitRefCas::{read, acquire, renew, release, list}`, `RefMarker`, `CasError`, `distclaim::{claim, renew, release, sweep_expired}`, `distwork::{select_and_claim, work_once}`.
- Concurrency: the remote is the arbiter; `acquire` makes at most 4 attempts before `kept changing` (`crates/hotsheet-ticketing/src/gitref_cas.rs:136`). Clocks are the claimer's and must be roughly synchronized (`crates/hotsheet-ticketing/src/gitref_cas.rs:15-17`).
- Errors and recovery: `CasError::Unreachable` versus `CasError::Git` (`crates/hotsheet-ticketing/src/gitref_cas.rs:110-118`); `list` drops markers it cannot parse (`crates/hotsheet-ticketing/src/gitref_cas.rs:212`). `distclaim::release` deletes without a lease check (`crates/hotsheet-ticketing/src/distclaim.rs:159-172`), and `sweep_expired` uses it (`crates/hotsheet-ticketing/src/distclaim.rs:229-243`).
- Configuration and environment: `distclaim` hard-codes the remote `origin` (`crates/hotsheet-ticketing/src/distclaim.rs:100`). No environment variables.
- Invariants: a lapsed marker is replaced with fencing `max(prev + 1, now_ms)`; a new ref starts at `max(now_ms, 1)` (`crates/hotsheet-ticketing/src/gitref_cas.rs:283-290`); a release only deletes the same `claim_id`.
- Tests: `crates/hotsheet-ticketing/src/gitref_cas_tests.rs` (`hs2_wjf0d8_a_lapsed_claim_is_taken_with_a_larger_fencing_token`, `hs2_wjf0d8_a_distclaim_marker_and_an_exact_claim_exclude_each_other`, `hs2_wjf0d8_an_unreachable_remote_is_reported_as_such`); unit tests in `crates/hotsheet-ticketing/src/distclaim.rs` (`sweep_reaps_only_expired_markers`) and `crates/hotsheet-ticketing/src/distwork.rs` (`two_workers_never_take_the_same_ticket`).

## Advisory claim rules and replay ledger (`orchAdvisoryClaims`)

- Modules: small modules `crates/hotsheet-ticketing/src/advisory_claim.rs`, `advisory_claim_v2.rs`, `advisory_claim_ledger.rs`.
- Responsibility: provider markers are evidence of intent and never an exclusive lease (`crates/hotsheet-ticketing/src/advisory_claim.rs:1-5`); `reconcile_claims` projects claim, renew and release events and flags conflicts (`crates/hotsheet-ticketing/src/advisory_claim.rs:77-165`); v2 operation ids carry a time and become inert after a 24 h horizon (`crates/hotsheet-ticketing/src/advisory_claim_v2.rs:10-101`). Jira marker storage is in `crates/hotsheet-extsync/src/jira.rs` (core area); the HTTP surface is `crates/hotsheet-server/src/provider_advisory_claims.rs` (server area).
- State and persistence: SQLite `HOME/advisory_claims/provisional.sqlite`, table `provisional_claims` keyed by project scope, connection, native id and operation id (`crates/hotsheet-ticketing/src/advisory_claim_ledger.rs:81-104`), opened by the server and the CLI (`crates/hotsheet-server/src/main.rs:400-403`).
- Types and entry points: `AdvisoryEvent`, `reconcile_claims`, `ProvisionalClaimLedger::{admit, settle}`, `ClaimReplayState`.
- Concurrency: SQLite busy timeout 5 s; the server wraps the ledger in a `Mutex` (`crates/hotsheet-server/src/lib.rs:987-991`).
- Errors and recovery: `admit` is idempotent and refuses a changed payload; caps of 1000 pending and 10000 total rows, settled rows older than 7 days pruned on admit (`crates/hotsheet-ticketing/src/advisory_claim_ledger.rs:15-17`, `crates/hotsheet-ticketing/src/advisory_claim_ledger.rs:106-210`).
- Configuration and environment: clock skew allowance 60 s (`crates/hotsheet-ticketing/src/advisory_claim_v2.rs:10-14`). No environment variables.
- Invariants: a release is a tombstone per operation; a renew must keep the worker and not shorten the expiry; more than one live claim is a conflict.
- Tests: unit tests in `crates/hotsheet-ticketing/src/advisory_claim.rs` (`hs2_bpkm76_concurrent_live_claims_are_conflicted`), `crates/hotsheet-ticketing/src/advisory_claim_v2.rs` (`hs2_0qeprw_late_same_id_marker_is_inert_after_terminal_horizon`), `crates/hotsheet-ticketing/src/advisory_claim_ledger.rs` (`hs2_bpkm76_provisional_admission_is_durable_and_idempotent`); `crates/hotsheet-server/tests/jira_advisory_claim_http.rs` (`hs2_bpkm76_provisional_claim_replays_after_restart_and_reconciles`).

## Resource claim service and local backend (`orchResourceClaims`)

- Modules: `crates/hotsheet-resource-claims/src/conformance.rs`, `crates/hotsheet-resource-claims/src/local` (`mod.rs`, `storage.rs`, `waiters.rs`); small modules `lib.rs`, `backend.rs`, `model.rs`, `service.rs`, `config.rs`, `codec.rs`, `token.rs`, `clock.rs`, `error.rs`, `interrupt.rs`.
- Responsibility: the blocking `ClaimBackend` contract, where `acquire` is a compare-and-swap with a monotonic fencing token unless the backend advertises `AdvisoryOnly` (`crates/hotsheet-resource-claims/src/backend.rs:11-57`); request validation (`crates/hotsheet-resource-claims/src/model.rs:13-47`); `ClaimService` request routing (`crates/hotsheet-resource-claims/src/service.rs:247-331`); configuration resolution (`crates/hotsheet-resource-claims/src/config.rs:71-163`); the machine-local file backend; and the conformance suite (`crates/hotsheet-resource-claims/src/conformance.rs:55`).
- State and persistence: `HOME/resource-claims/key` (32 random bytes, 0600, created with no-clobber, `crates/hotsheet-resource-claims/src/codec.rs:48-126`); `HOME/resource-claims/namespaces/<ns>/state.json`, `state.lock`, `waiters/<ULID>`; project-scoped namespaces under `HOME/resource-claims/projects/<hash16>/` (`crates/hotsheet-resource-claims/src/config.rs:112-122`). State files are staged, `fsync`ed, persisted and the directory `fsync`ed (`crates/hotsheet-resource-claims/src/local/storage.rs:153-175`); a released resource keeps its record so the fencing counter survives (`crates/hotsheet-resource-claims/src/local/storage.rs:14-18`).
- Types and entry points: `ClaimBackend`, `LocalBackend::{acquire, acquire_wait, renew, release, verify_fencing}`, `ClaimService::{new, with_project, with_max_wait, request}`, `Grant`, `Claim`, `ClaimError`, `InterruptGuard`, `held_namespaces`.
- Concurrency: every call blocks the calling thread; the server runs them in `spawn_blocking` (`crates/hotsheet-server/src/routes/resource_claims.rs:96`). One OS lock per namespace, held only inside `transact`; waiters are woken after the lock is dropped (`crates/hotsheet-resource-claims/src/local/mod.rs:112-136`). Waiters bind a loopback UDP socket and wake on a 1-byte datagram (`crates/hotsheet-resource-claims/src/local/waiters.rs:29-160`). `InterruptGuard` is process-global and Unix-only (`crates/hotsheet-resource-claims/src/interrupt.rs:21-112`).
- Errors and recovery: 12 error codes with HTTP mapping (`crates/hotsheet-resource-claims/src/error.rs:5-61`, `crates/hotsheet-resource-claims/src/service.rs:93-104`); corrupt or wrong-schema state is never overwritten; a crashed holder keeps its lease until expiry; a crashed waiter's file is removed by a later wake once 60 s past its deadline (`crates/hotsheet-resource-claims/src/local/waiters.rs:19`).
- Configuration and environment: lease and wait at most 24 h, metadata at most 16 entries and 4096 bytes with `plain:`, `hmac-sha256:` or `enc:v1:` values (`crates/hotsheet-resource-claims/src/model.rs:13-23`, `crates/hotsheet-resource-claims/src/model.rs:255-291`); 4096 resources and 256 waiters per namespace (`crates/hotsheet-resource-claims/src/local/waiters.rs:17`); server wait capped at 55 s (`crates/hotsheet-server/src/routes/resource_claims.rs:32`). No environment variables are read in the crate.
- Invariants: liveness is `expires_at_ms > now` (`crates/hotsheet-resource-claims/src/local/mod.rs:104-108`); renewal tokens are stored only as an HMAC digest locally (`crates/hotsheet-resource-claims/src/token.rs:73-79`); `held_namespaces` enumerates only the machine local backend (`crates/hotsheet-resource-claims/src/service.rs:34-38`).
- Tests: `crates/hotsheet-resource-claims/tests/transitions.rs` (`hs2_h3wppy_expiry_frees_the_resource_and_fences_the_old_holder`), `crates/hotsheet-resource-claims/tests/waiting.rs`, `crates/hotsheet-resource-claims/tests/cross_process.rs` (`hs2_h3wppy_concurrent_processes_get_exactly_one_grant`, `hs2_h3wppy_a_crashed_holder_keeps_its_lease_until_expiry_only`), `crates/hotsheet-resource-claims/tests/conformance.rs`, `crates/hotsheet-resource-claims/src/config_tests.rs`, `crates/hotsheet-cli/tests/resource_claims.rs` (`hs2_qgy1nn_many_stopped_waits_never_fill_the_namespace`).

## Remote resource claim backends (`orchResourceBackends`)

- Modules: `crates/hotsheet-resource-claims/src/external` (`backend.rs` listed separately as `crates/hotsheet-resource-claims/src/external/backend.rs`; small modules `manifest.rs`, `runner.rs`, `approval.rs`, `mod.rs`), `crates/hotsheet-resource-claims/src/upstash` (`crates/hotsheet-resource-claims/src/upstash/mod.rs`; small modules `transport.rs`, `scripts.rs`); small module `gitref.rs`.
- Responsibility: Git-ref backend over `GitRefCas` with an offline provisional fallback (`crates/hotsheet-resource-claims/src/gitref.rs:58-79`); Upstash Redis REST backend with atomic Lua scripts using Redis `TIME` (`crates/hotsheet-resource-claims/src/upstash/scripts.rs:18-133`); external plugin subprocesses described by `HOME/claim-backends/<id>/manifest.toml` and approved by digest (`crates/hotsheet-resource-claims/src/external/manifest.rs:14-24`, `crates/hotsheet-resource-claims/src/external/approval.rs:18-39`).
- State and persistence: Git refs `refs/hotsheet/resource-claims/<ns>/<res>`; provisional fallback under `HOME/resource-claims/provisional/<configuration>/`; Upstash keys `<prefix>:v1:<ns>:c:<res>`, `:f:<res>`, `:r`, `:namespaces`, channel `:ch:<res>` with default prefix `hs2rc` (`crates/hotsheet-resource-claims/src/upstash/mod.rs:38`, `crates/hotsheet-resource-claims/src/upstash/mod.rs:98-112`); `HOME/claim-backends/approvals.json`, written by temp file and persist with no lock (`crates/hotsheet-resource-claims/src/external/approval.rs:77-90`).
- Types and entry points: `GitRefBackend`, `UpstashBackend`, `ExternalBackend`, `PluginManifest`, `run_plugin`.
- Concurrency: Git refs and Upstash scripts are the arbiters. Plugins run without a shell; two threads drain stdout and stderr and the child is polled every 10 ms (`crates/hotsheet-resource-claims/src/external/runner.rs:42-110`). Upstash waits subscribe over SSE (`crates/hotsheet-resource-claims/src/upstash/mod.rs:443-546`).
- Errors and recovery: Git-ref `FailClosed` maps unreachable to `BackendUnreachable`, `Provisional` relabels local fallback claims `AdvisoryOnly`; `list` and `namespaces` do not fall back (`crates/hotsheet-resource-claims/src/gitref.rs:187-193`, `crates/hotsheet-resource-claims/src/gitref.rs:276`). Git-ref waits with a non-zero timeout are `Unsupported` (`crates/hotsheet-resource-claims/src/gitref.rs:198-213`). Upstash makes 3 attempts on HTTP 429 and gives up a failing stream after 6 failures (`crates/hotsheet-resource-claims/src/upstash/mod.rs:41-47`). A plugin past its timeout is killed; the reply is the last JSON stdout line; an edited plugin is refused until approved again (`crates/hotsheet-resource-claims/src/external/backend.rs:315-371`).
- Configuration and environment: settings `repository`, `remote` (Git-ref), `url`, `prefix` (Upstash), `plugin` (external); plugin `timeout_seconds` default 30, clamped to 1 to 300 (`crates/hotsheet-resource-claims/src/external/manifest.rs:25`); secrets from the OS credential store account `resource-claims.<config>.<key>` (`crates/hotsheet-resource-claims/src/external/backend.rs:67-70`); Upstash URLs must be HTTPS or loopback HTTP (`crates/hotsheet-resource-claims/src/upstash/transport.rs:62-88`).
- Invariants: tokens reach plugins only as a digest; secrets travel on stdin, never argv or environment; Git-ref, Upstash and external store an unkeyed SHA-256 token digest (`crates/hotsheet-resource-claims/src/token.rs:81-84`).
- Tests: `crates/hotsheet-resource-claims/src/gitref_tests.rs` (`hs2_wjf0d8_offline_fail_closed_and_provisional_modes`, `hs2_322zsz_the_git_ref_backend_passes_the_conformance_suite`), `crates/hotsheet-resource-claims/tests/upstash.rs` (`hs2_k9j1rk_a_rate_limit_is_retried_a_bounded_number_of_times`), `crates/hotsheet-resource-claims/tests/external_plugin.rs` (`hs2_322zsz_secrets_travel_only_on_stdin_never_argv_or_environment`); `crates/hotsheet-resource-claims/tests/upstash_live.rs` runs only with `HOTSHEET_TEST_UPSTASH_URL` and `HOTSHEET_TEST_UPSTASH_TOKEN`.

## Job store and monitor (`orchJobStore`)

- Modules: `crates/hotsheet-jobs/src/store.rs`, `crates/hotsheet-jobs/src/monitor.rs`, `crates/hotsheet-jobs/src/watch.rs`; small modules `lib.rs`, `model.rs`, `state.rs`, `steps.rs`, `feed.rs`, `lock.rs`, `probe.rs`, `slot.rs`, `signal.rs`, `ci.rs`, `fixture.rs`, `clock.rs`, `error.rs`. Process records are in `crates/hotsheet-process-journal/src/lib.rs` (core area).
- Responsibility: Job records with leases, feeds and duration history; the single-instance watch monitor; file-change waiters; and the CI gate view `gate_of` and `wait_for_gate_change` consumed by orchestration (`crates/hotsheet-jobs/src/ci.rs:148-270`). HTTP and credentials are in the CLI (`crates/hotsheet-cli/src/dispatch/job_ci_rest.rs`).
- State and persistence: under `HOME/jobs/<checkout>/`: `.lock`, `revision` (temp file and persist, no `fsync`), `history.json`, `<ULID>/job.json` (1 MiB, `fsync`ed), `<ULID>/feed.jsonl` (append, no `fsync`) (`crates/hotsheet-jobs/src/store.rs:29-35`, `crates/hotsheet-jobs/src/store.rs:883-900`, `crates/hotsheet-jobs/src/feed.rs:130-150`); monitor slot `HOME/jobs/.monitor.lock`, `.monitor.json`, `.monitor.stop` (`crates/hotsheet-jobs/src/slot.rs:16-19`).
- Types and entry points: `JobStore::{create, acquire, update, end, release, cancel, reconcile}`, `Job`, `JobStatus`, `Liveness`, `Monitor::tick`, `ensure_monitor_running`, `ChangeWaiter`, `BackgroundWatcher`, `JournalProbe`, `ensure_ci_watch`, `gate_state`.
- Concurrency: the monitor is one thread holding `.monitor.lock` for its life, then one checkout `.lock` at a time (`crates/hotsheet-jobs/src/monitor.rs:225-254`); each `BackgroundWatcher` runs one `hotsheet-path-watcher` thread (`crates/hotsheet-jobs/src/watch.rs:182-307`); reads take no lock. The lock file is opened read-only so watchers see no write (`crates/hotsheet-jobs/src/lock.rs:14-27`).
- Errors and recovery: an expired lease becomes `lost` when the probe says gone, or after a further 5 minutes when unknown (`crates/hotsheet-jobs/src/store.rs:676-718`); the monitor reconciles with `NoProbe` (`crates/hotsheet-jobs/src/monitor.rs:311`). Pruning removes temp files, damaged directories and expired finished Jobs, leaving unknown versions alone (`crates/hotsheet-jobs/src/store.rs:905-932`). Feed sequence numbers may be skipped by a crash but are never reused (`crates/hotsheet-jobs/src/feed.rs:80-128`). Transient poll errors back off exponentially to 300 s (`crates/hotsheet-jobs/src/monitor.rs:444-566`).
- Configuration and environment: lease 60 s, lost grace 5 min, retention 15 min (succeeded, cancelled) and 24 h (failed, lost), 64 Jobs per checkout, 256 KiB feed per Job (`crates/hotsheet-jobs/src/store.rs:54-65`); monitor poll 15 s up to 120 s, idle exit 30 s (`crates/hotsheet-jobs/src/monitor.rs:119-128`). No environment variables are read in the crate; debug builds of the CLI read `HOTSHEET_JOB_WATCH_FIXTURES` (`crates/hotsheet-jobs/src/fixture.rs:17-40`).
- Invariants: terminal Job states never resume; only watch Jobs may go `lost` to running again (`crates/hotsheet-jobs/src/state.rs:10-24`); a report from an older lease generation cannot overwrite a newer one (`crates/hotsheet-jobs/src/store.rs:1004-1017`).
- Tests: `crates/hotsheet-jobs/tests/adversarial.rs` (`a_stalled_watch_lease_can_be_taken_over_but_a_live_one_cannot`, `a_crash_mid_write_leaves_the_last_good_snapshot_and_is_swept`), `crates/hotsheet-jobs/tests/monitor.rs` (`a_dead_monitors_job_stalls_and_the_next_monitor_takes_it_over`), `crates/hotsheet-jobs/tests/concurrency.rs`, `crates/hotsheet-jobs/tests/transitions.rs`, `crates/hotsheet-jobs/tests/waiter.rs`.

## CI watch adapters (`orchCiAdapters`)

- Modules: `crates/hotsheet-jobs/src/github.rs`, `crates/hotsheet-jobs/src/gitlab.rs`, `crates/hotsheet-jobs/src/azure.rs`, `crates/hotsheet-jobs/src/bitbucket.rs`, `crates/hotsheet-jobs/src/circleci.rs`, `crates/hotsheet-jobs/src/jenkins.rs`; small module `buildkite.rs`.
- Responsibility: each adapter implements a watch source over the `GithubApi` REST port (`crates/hotsheet-jobs/src/github.rs:476-517`) and decides green, red, cancelled or superseded for a commit. GitHub: success is green; failure, timed_out, startup_failure and action_required are red; a commit unknown after 30 minutes fails as `unknown` (`crates/hotsheet-jobs/src/github.rs:683-748`, `crates/hotsheet-jobs/src/github.rs:906-913`).
- State and persistence: none of their own; observations land in the Job record through the monitor.
- Types and entry points: `poll`, `decide`, `cancel` per adapter; `Observed`, `WatchError::Transient`.
- Concurrency: called on the monitor thread.
- Errors and recovery: HTTP 404 on the run list ends the watch as `Gone`; every other failure is `Transient` with an optional retry-after (`crates/hotsheet-jobs/src/github.rs:837-841`). GitHub reads one page of 30 runs (`crates/hotsheet-jobs/src/github.rs:20`); CircleCI reads at most 3 pipelines and 4 job lists per poll (`crates/hotsheet-jobs/src/circleci.rs:32-34`).
- Configuration and environment: credentials and API roots are read by the CLI, not this crate: `GH_TOKEN`, `GITHUB_TOKEN`, `HOTSHEET_GITHUB_API_URL`, `GITLAB_TOKEN`, `HOTSHEET_GITLAB_API_URL`, `BUILDKITE_API_TOKEN`, `CIRCLECI_TOKEN`, `HOTSHEET_JENKINS_URL`, `JENKINS_USER`, `JENKINS_API_TOKEN`, `AZURE_DEVOPS_EXT_PAT`, `BITBUCKET_ACCESS_TOKEN`, `BITBUCKET_USERNAME`, `BITBUCKET_API_TOKEN` (`crates/hotsheet-cli/src/dispatch/job_ci_rest.rs:1-32`, `crates/hotsheet-cli/src/dispatch/job_github.rs:16`).
- Invariants: a newer diverged run supersedes the older commit's watch.
- Tests: `crates/hotsheet-jobs/tests/github.rs` (`a_commits_run_is_followed_from_queued_to_green`, `a_lost_watch_reads_unknown_and_resumes_under_the_same_job`), `crates/hotsheet-jobs/tests/gitlab.rs`, `crates/hotsheet-jobs/tests/buildkite.rs`, `crates/hotsheet-jobs/tests/circleci.rs`, `crates/hotsheet-jobs/tests/jenkins.rs`, `crates/hotsheet-jobs/tests/azure.rs`, `crates/hotsheet-jobs/tests/bitbucket.rs`.
