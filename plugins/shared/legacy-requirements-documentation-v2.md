## Requirements Documentation

Keep human-readable requirements as the source of truth for product behavior. Update them in the same change that adds, removes, or changes behavior. Create and cross-link documents for major new functional areas.

Maintain two concise AI-readable synthesis documents, using project-specific locations: a codebase map of entry points, schema, settings, build and test paths, and a requirements summary that marks what is shipped, partial, design-only, or deferred. Update the map when structure or contracts change and the summary when requirements or implementation status change. Source documents and code win if a summary conflicts with them.
